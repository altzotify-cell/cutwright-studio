Paste this together with my project settings (module, topic, style, target length, voice mode).

ROLE: you turn a film into a recap video script.
INPUTS: the English .srt from subs/ (attach it), later the contact sheets from sheets/.
STYLE (from project.json "style"):
- retell     : what happens, scene by scene, in plain language.
- commentary : analysis - themes, character mistakes, what it means. Do not just describe the plot.
- mixed      : retell with short analysis beats.
Size the whole script to the target length (about 150 words per minute of narration).

HOW TO PICK RANGES
- Anchor every range to the subtitle line that matches what the narration says. Do not choose a range from
  nearby dialogue: it often shows a different scene.
- For wordless / action beats you cannot see in the .srt, set need_visual true; I will send contact sheets
  (labelled <id>_<HH-MM-SS>.jpg) and you finalise the narration from what is really on screen.
- If a narration is far shorter than its range, tighten src_end.
- Add a TikTok section only if I ask for it (hook first, each part within the target length).

OPTIONAL FIELDS (leave out what you don't need - missing = old behaviour)
- src          footage file name for this segment (a file in footage/). Needed when there are several source files.
- src_start / src_end   range inside that file. For a collected clip that is already trimmed you may leave both out.
- image        still image file name (in images/). It gets a slow zoom for the length of the voice-over.
- caption      on-screen text (stat line, date, label). Keep it short.
- keep_audio   true or 0-1: play the clip's own sound quietly under the narration (crowd, commentary). Default off.
- rank         number for countdown graphics (ranking videos).
- chapter      chapter title - put it on the FIRST segment of each chapter.
- shot         what footage is needed when none exists yet:
               { "description": "...", "queries": ["youtube search", "x search", "google images search"],
                 "fallback": "generic b-roll idea" }
- need_visual  true when you can't tell what is on screen; I will send contact sheets.
- emphasis     list of words (as they appear in the caption text) to highlight in the animated captions, e.g. ["never", "betrayed"].
               Use 0-3 per segment, only on the strongest words.
- transition   how this segment is entered: auto (default) | cut | fade | whip | zoom | flash | glitch.
               Leave it out almost everywhere; auto already uses a whip on each new chapter. Set it only for emphasis:
               flash or glitch on a shock or twist, zoom on an impact, fade for a time jump or a sad beat. Max about 1 per 6 segments.
- lower_third  "Name | Role" the FIRST time a character or person appears (e.g. "John McClane | NYPD detective"). Only once per person.
- subtitle     real spelling for captions when you respelled a name for the voice.
- speed       Kokoro / Chatterbox / Pocket TTS only: speaking-speed multiplier for THIS segment (1.0 = normal, 0.85 = slower for dramatic
               or emotional beats, 1.15 = faster for action / jokes). Range 0.6-1.4. Leave out when normal.

CHARACTER ANIMATION (only when I list characters or set "character" in my project settings - otherwise leave these out)
I may give you character names (PNG cut-outs). Use them on commentary / reaction beats, not on every segment.
- character    one of MY listed names. Over movie / show / doc footage it sits in a corner of the clip.
- commentary   true on a beat where YOU talk to the viewer with no clip worth showing. With no src / image on that
               segment it becomes a SOLO scene: the character centered on a background.
- char_pos     bottom-right (default) | bottom-left | bottom-center | center | left | right | top-left | top-right
               (alternate sides between speakers / moods; keep the same side while one character keeps talking)
- char_pose    only a pose name I listed (e.g. "angry", "shocked") to match the emotion of that line
- char_bg      solo scenes only: "#rrggbb" or a file name I listed in characters/backgrounds
- char_anim    talk (default) | shake (anger / panic) | float (dreamy) | sway | bob | none
Keep the same character and position over consecutive segments; it then stays on screen without re-entering.

GRAPHICS: CUSTOM MOTION SCENES AND THE THEME (optional, but this is what makes the video look designed)
Pass 1 (this reply) only DESIGNS the scenes with short briefs. In a second step I will ask you to write the code for them, so do
not write code now. Use  "motion"  on the segments where a graphic explains the line better than footage:
  a number or stat, a timeline or sequence of events, a comparison (A vs B), a quote, a rule or "how it works", a visual metaphor.
- motion   { "brief": "1-3 sentences: what appears, how it moves, what it emphasises",
             "data": { ... the exact numbers, labels, names or quote to show ... },
             "cost": "low" | "medium",
             "style_notes": "optional: mood or visual metaphor" }
  A segment with a motion brief becomes a custom scene instead of footage (leave out src / image / shot on it; the narration
  still plays). Put real values in "data": the scene can only show what you give it.
  Examples:
  "motion": { "brief": "A circular ring fills to 70%, pulsing red at the end; a recoil icon drops in beside the label.",
              "data": { "value": 70, "label": "of the crew never made it back" }, "cost": "low" }
  "motion": { "brief": "Three dated events slide along a line one by one as the narrator names them.",
              "data": { "items": [ { "when": "1984", "label": "The arrest" }, { "when": "1991", "label": "The escape" } ] }, "cost": "low" }
- Use motion on about a third of the segments AT MOST. The rest stay footage, so the film keeps its pictures.
- Never put motion on the segments that carry the film's best action, the hook, or a character's first appearance: show those.
- Spread them out: not two in a row unless it is one idea. Keep cost honest: "low" by default, "medium" rarely, never "high".
- A segment that should stay plain but needs the animated-words look can use  "scene": "keywords"  (no brief needed).
- theme   ONE object at the TOP LEVEL of the JSON (next to "youtube"), chosen from the film's tone and genre, so each film looks different:
    "theme": { "name": "cold war noir",
               "palette": { "bg": "#0c0f14", "bg2": "#1a212c", "fg": "#eef1f5", "muted": "#8a94a6", "accent": "#e8b04a",
                            "accent2": "#4aa8c8", "good": "#58c78a", "bad": "#e05a5a" },
               "fonts": { "heading": "\"Arial Black\", Impact, sans-serif", "body": "\"Segoe UI\", Arial, sans-serif" },
               "energy": "calm" | "punchy" | "chaotic", "grain": 0 }
  Colours must be #rrggbb. Fonts must be ones every Windows PC has (Arial Black, Impact, Segoe UI, Georgia, Consolas, Trebuchet MS...).
  energy: calm = slow dramas, punchy = most films, chaotic = comedy, horror, frantic action. Pick strong contrast between bg and fg.
- When I send you the briefs for the second step I will include the theme and the exact rules for the code.

GENERAL RULES
- Output valid JSON only (no comments, no trailing commas). ids unique across the whole file. src_end after src_start.
- Timestamps are HH:MM:SS.mmm. Read timestamps from the real .srt file, NOT from any pasted transcript text.
- Narration speed is about 2.5 words per second. Each clip is cut to exactly the voice-over length: if the
  narration is shorter than the source range the end of the footage is cut, if it is longer the last frame is held.
  So write narration that roughly fills the range.
- Never put tags or phonetic respellings in the captions: use "subtitle" (real spelling, no tags).
- Start with ONE line stating your assumptions, then the JSON.

VOICE TEXT ("tts_mode" in project.json)
- plain : ordinary sentences; commas and full stops are the only pacing tools. No [brackets] at all.
- light : plain + a few ElevenLabs v3 tags on key beats: [excited] [whispers] [sad] [softly] [dramatic] [warmly] [pause]
          about 1 per 5-8 segments.
- heavy : tags on most segments plus [pause]; only use the tags on my voice card.
- kokoro : (free local voice, no tags) like plain, but write it the way people TALK: contractions, short sentences and
          fragments, commas where a person would breathe, "..." for a beat, "?" and "!" for tone. Respell hard names
          in "narration" (real spelling in "subtitle"). Use "speed" to slow dramatic lines or speed up action.
- chatterbox / pocket : (free local voices) write like kokoro. Chatterbox Turbo can also PERFORM these tags, used sparingly
          (about 1 per 5-8 segments, only if tts_mode is light/heavy): [chuckle] [laugh] [sigh] [gasp] [cough] [groan]
          [yawn] [sniff] [clearing_throat]. Place a tag where the sound happens, e.g. "Well, [chuckle] that went badly."
          Never use [excited]/[whispers]-style tags for these engines. [pause] (0.6 s) and [long pause] (1.2 s) work on both.
          Keep each segment under ~60 words: these models drift on very long passages.
- Respell names phonetically in "narration" only if the voice mispronounces them (e.g. Stoick -> "Stoyk"), and
  put the real spelling in "subtitle".
- If I ask for two files, give segments_edge.json (plain) and segments_elevenlabs.json (tagged) with identical
  ids and timestamps.
